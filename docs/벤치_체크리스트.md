# 벤치 체크리스트 (인쇄용, 아래 표는 보드 5기 예시)

> ★**2026-09-26 전파법 정리**: 개인이 쓰려고 들여온 **모델별 1대**는 면제확인 신청 없이 쓸 수 있다. **같은 모델을 2대 이상** 들이거나 단체 명의로 여러 대를 들이면 연구·기술개발용 면제확인이 필요하다. 참여자는 각자 **본인 명의로 1대씩** 산다. 5기 벤치는 그 면제확인을 받은 경우의 예시다.

> **한 줄 요약**: 보드 도착 → 서버(LAN) 기동 → 유닛별 5게이트(G0 플래시 → G1 GPS전원 → G2 풀사이클 → G3 버퍼플러시 → G4 HTTPS) → 공통 2항(슬립 전류·조립 이행). **전 게이트 통과 전엔 조립·방류 없음.** 근거: [firmware/README](../firmware/README.md) 벤치 재검증 체크리스트 · [조립_가이드](조립_가이드.md).

## 0. 사전 준비 (보드 도착 전에 완료)

| ✅ | 항목 |
|---|---|
| ☐ | Arduino IDE + ESP32 core 3.0.x, 보드 "ESP32 Dev Module" |
| ☐ | 라이브러리: **lewisxhe/TinyGSM-fork**(★스톡 TinyGSM 제거), TinyGPSPlus, ArduinoHttpClient |
| ☐ | 수신 서버 v1.1 확인: `python ingest_server.py 8770 0.0.0.0` — 기동 로그에 `FF-ID schema v1.1` |
| ☐ | ★★**서버를 공인 인터넷에 노출** — 보드는 Wi-Fi가 아니라 **LTE(통신사 망)**로 접속하므로 **LAN 사설 IP(192.168.x.x)로는 절대 도달 불가**(통신사 NAT). 둘 중 하나: ①`ngrok tcp 8770` → 발급된 `호스트:포트`를 펌웨어 `SERVER_HOST/PORT`에 ②공유기 포트포워딩(8770)+공인 IP. ※`ngrok http`는 TLS라 평문 클라이언트로 안 붙음(펌웨어 주석 참조) |
| ☐ | 방화벽 8770 인바운드 허용(포트포워딩 경로일 때) |
| ☐ | (서버 드라이런) curl로 v1.1 ping POST → `ok:true`, 같은 seq 재전송 → `dup:true`, `/api/live.geojson`에 궤적 |
| ☐ | SIM: **참여자 본인 명의 국내 유심**(권장 헬로모바일 슬림 500MB, LG U+ 망, 음성 포함 요금제, 휴대폰에서 먼저 개통 후 보드로 옮김). LG U+는 더 이상 제외하지 않는다(보드 실시험 전). 먼저 [`sim_check`](../firmware/sim_check/sim_check.ino)로 망 등록을 확인한다 |
| ☐ | 셀: **무보호 삼성 30Q** + **외부 홀더** + **PCM(보호모듈, 과방전·과충전·단락 차단; 3.7V 1셀, 연속 3A 이상)** → 보드 뒷면 홀더 단자. 보드 홀더는 비움. 유닛 수만큼 충전 |
| ☐ | 유닛 ID 라벨 5장 인쇄: `ff-kr-bs-u0001` ~ `u0005` |

## 1. 유닛별 게이트 (보드마다 반복)

- **G0 플래시**: `DEVICE_ID`를 유닛 고유값으로 바꿔 업로드(`BENCH_HTTP 1`, `SLEEP_MINUTES 5`, ★**`ADAPTIVE_INTERVAL false`를 함께** — `true`면 전압 기반 간격이 `SLEEP_MINUTES`를 덮는다). ★셀 장착 후 진행(USB 단독 급전 금지 — 2A 피크 브라운아웃).
- **G1 GPS 전원 관문**: 창가/야외에서 첫 웨이크 로그 확인. fix 성공 또는 실패라도 `NMEA chars>0`이면 통과. **`chars=0`이면 중단** → [firmware/README](../firmware/README.md) 체크리스트 1번대로 **USB를 뺀 배터리 급전 상태에서 V3V를 잰다**. 회로도상 L76K는 모뎀 전원에 의존하지 않으므로(GPIO12 게이트) modemPowerOn 순서를 바꿀 필요는 없다.
- **G2 풀사이클**: fix → POST 200 → 딥슬립 → 웨이크, 3주기 연속. 서버에서 `seq`가 1씩 증가, `ts_fix`·`sample_interval_s`·`batt` 수신 확인.
- **G3 버퍼 플러시**: LTE 안테나 분리 → 2~3주기(로그에 "버퍼 보존" 확인) → 안테나 재결합 → 다음 웨이크에 **밀린 레코드가 오래된 순으로 몰아 전송**되고 지도 궤적이 ts_fix 순으로 조립되는지.
- **G4 HTTPS 빌드**(대표 1기만): `BENCH_HTTP 0`(A76XXSSL)로 컴파일·업로드 → openc로 POST 성공. 확인 후 벤치용은 다시 `BENCH_HTTP 1`.

|---|---|---|---|---|---|
| ff-kr-bs-u0001 | ☐ | ☐ | ☐ | ☐ | G4 HTTPS 대표 ☐ |

## 3. 다음 단계

모든 유닛이 G0에서 G3 과정을 통과하면 [조립_가이드](조립_가이드.md) 3장 조립으로 넘어간다. 조립과 밀봉을 마친 뒤 T1에서 T6 단계를 수행한다. 상세 내용은 [VERIFIED_BUILD_TEST](../hardware/VERIFIED_BUILD_TEST.md)를 참고한다. 방류하기 전에 [PRELAUNCH_RECOVERY_CHECKLIST](../hardware/PRELAUNCH_RECOVERY_CHECKLIST.md)를 확인한다.

## 4. 솔라 부록 — G5 수확 (6V 평판 패널, 참여자 키트 기본)

> ★**2026-09-26 갱신**: 솔라는 **뚜껑 위 6V 평판 패널 SZH-SPB017**이다(박막 랩 아님). G5 과정에서 **뚜껑 위 바깥과 용기 안쪽을 나란히 놓고 충전 전류와 온도를 비교**하여 위치를 확정한다. 패널 개방전압도 이때 잰다. 아래 ④ a-Si(비정질 실리콘) 노화, ⑥ 외부 컨트롤러 항목은 옛 박막과 외부 충전 설계 기준이다. 지금은 보드에 CN3065를 내장하므로 ⑥은 보드 잠 전류 측정에 포함한다.

솔라 유닛은 위 G0에서 G3 과정을 마친 뒤 조립과 T1에서 T6 과정을 거친다. 이에 더해 **G5 수확 특성화 단계와 T7 패널 장착 자기복원 단계**를 통과해야 방류할 수 있다. G5 7스텝(인라인 전류계/쿨롱카운터, 최소 USB 전류계로 대체 가능):

| ✅ | 단계 |
|---|---|
| ☐ | ① 완전한 햇빛과 정적 최적 자세를 기준으로 충전전류를 잰다. |
| ☐ | ② **뒹구는 자세** 시간평균 전류(자기복원체는 윗면 자세가 고정·배는 항상 어두움) |
| ☐ | ③ 모의 탁도나 수막을 얹고 다시 측정한다. |
| ☐ | ④ 노화 반영(a-Si는 초기 10~30% 안정화 후) |
| ☐ | ⑤ 일주 적분으로 수확 H를 구한다. 단위는 mAh/day이다. |
| ☐ | ⑥ **야간 컨트롤러 정지전류를 실측한다.** mA급 MPPT(최대 전력점 추적) 방식이면 순손해가 난다. 따라서 선형 방식이나 야간게이트를 쓴다. |
| ☐ | ⑦ 목표 핑 실측 소비 D와 비교한다. **손익분기 H*는 약 132 mAh/day이다.** 이는 60분 간격과 모뎀 오프를 기준으로 한다. 연장계수 1/(1−H/D)만, ★**일수 인용 금지** |

**판정**: H가 D 대비 순증이 아니면 "보험 트리클"로 라벨(배터리가 잔류를 독립 감당). <0℃면 저온 컷오프로 H→0(겨울은 솔라 아님). 상세=[TIER1_5 §4](../hardware/TIER1_5_SOLAR_DRIFTER.md).
